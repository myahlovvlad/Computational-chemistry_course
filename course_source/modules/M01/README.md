## Зачем выполнять

Исследователь хочет использовать расчёт для выбора следующего измерения. Среднее качество прогноза выглядит приемлемо, но в архиве обнаруживается крупное индивидуальное расхождение. Студент проверяет, что именно сравнивал, расследует несовместимые единицы и выбирает эксперимент, который уменьшит неопределённость. Решение о нехватке доказательств — допустимый научный результат.

1. [01_guided_case.ipynb](01_guided_case.ipynb): вводный язык дисциплин → реальный Delaney/DeepChem snapshot → прогноз студента → остатки и график → крупное фактическое отклонение → аудит источника → следующее измерение → направленное ребро карты.
2. [02_independent_lab.ipynb](02_independent_lab.ipynb): другие подлинные строки → расследование искусственно внесённого дефекта импорта → выбор следующей проверки для досье B (аторвастатин/HMGCR/печёночная экспозиция).

А/В связаны исследовательским методом и досье, а не ложным равенством endpoints. ESOL не измеряет BBB, A2A-affinity или печёночную экспозицию. Основные макрокейсы и их неготовые этапы описаны в [архитектуре курса](../../CURRICULUM_TWO_MACROCASES_DOSSIER.md); здесь реализовано только введение M01. Остальные 13 модулей не переписаны.

Общая [инструкция Windows/Linux](../../SETUP_WINDOWS_LINUX.md) остаётся справочной; следующие команды используют проверяемый scoped project. Установите uv по [официальной инструкции](https://docs.astral.sh/uv/getting-started/installation/), если его ещё нет.

Из корня репозитория, одинаково на Windows/Linux:

```text

uv run --project course_source/modules/M01 --frozen python course_source/modules/M01/fetch_data.py --from-file Labs/datasets/esol.csv
```

Если локального snapshot нет, уберите `--from-file Labs/datasets/esol.csv`: один раз потребуется сеть. Ни один notebook не скачивает данные и не устанавливает пакеты в ячейке. После подготовки работает offline. Загрузчик отказывается принять другой hash и не перезаписывает отличающийся исходник.

Выберите ядро **M01 · scientific evidence · uv (no RDKit)**. Оно запускается через uv, относится только к `.venv` внутри M01 и не меняет ядра остальных модулей. После переноса папки повторите регистрацию. В IDE также выбирайте эту среду для M01. Будущие приложения/CLI разрабатываются в IDE; в M01 notebook исследует данные и сохраняет собственный журнал.

## Артефакты и оценка

Guided создаёт JSON и parity-график. В самостоятельной работе нужны residual CSV/график, исправленная производная таблица с сохранёнными ID, объяснение дефекта импорта, исследовательский вопрос/решение и собственное ребро карты. `create_dossier` создаёт личные файлы и копию [стартер-досье](../../RESEARCH_DOSSIER_STARTER.md), сохраняя существующее содержимое. По умолчанию всё пишется в игнорируемый `learner_work/`; переопределение — переменная `M01_WORK_DIR`.

Три кейса по 4 критерия (0–1 каждый): постановка/источник; метод/артефакт; диагностика/контроль; решение/ограничение. Всего 12. Половина балла — релевантная, но неполная аргументация; ноль — отсутствие результата или неподдержанный вывод. Правильность первоначального прогноза сама по себе не оценивается.

Инварианты и формат не являются оцениванием научного вывода. Пустые ответы дают NOT_RUN, корректный формат не подменяет проверку содержания. В `instructor/` отдельно находятся эталоны, численный скрипт и рубрика. При выдаче оцениваемого пакета преподаватель отделяет их от student-файлов; публичный GitHub не обеспечивает скрытность ответов.

## Проверка и история

```text
uv run --project course_source/modules/M01 --frozen python -m unittest discover -s course_source/modules/M01/tests -p test_*.py -v
uv run --project course_source/modules/M01 --frozen python course_source/modules/M01/run_checks.py --output <новый-каталог>
```

`run_checks.py` сохраняет точные argv, версии, входные SHA256, stdout/stderr, исполненные копии обоих notebooks, авторский reference и изображения. Отдельно различает guided execution, пустой scaffold и instructor solution. Не перезаписывает прошлое evidence и learner-owned файлы.

Авторские тексты лежат в `content/`, код ячеек — в `lesson_code.json`. `build_notebooks.py` собирает из них ровно два Notebook. Правки вносятся в эти источники, затем книги пересобираются и исполняются заново; прежние outputs не считаются доказательством новой редакции. Вопросы P01–P12 требуют собственного рассуждения, три короткие проверки дают обратную связь по выбранному компоненту. Они не заменяют научную оценку ответа.

Предыдущие синтетические 2×2 notebooks сохранены в истории commit `a803d90`. Они не являются главным реальным кейсом и не объявляются готовыми этой проверкой. Существующие исторические аудиты и benchmarks относятся к своим версиям; новая проверка M01 не сертифицирует весь курс или Stepik.
