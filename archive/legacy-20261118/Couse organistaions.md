### 4. ИНЖЕНЕРНЫЙ КОД (БЛОК ИССЛЕДОВАТЕЛЯ)

100% рабочий, типизированный код с валидацией.

```python
import logging
from typing import List, Dict, Optional
from rdkit import Chem
from rdkit.Chem import Descriptors, MolStandardize

# Настройка логирования для AI-factory (отслеживание ошибок в пайплайне)
logging.basicConfig(level=logging.INFO, format='%(asctime)s - %(levelname)s - %(message)s')

def standardize_and_featurize(smiles: str) -> Optional[Dict[str, float]]:
    """
    Очищает молекулу и вычисляет ключевые дескрипторы.
    """
    try:
        # WHY: Парсинг SMILES. Без этого мы не можем перейти к графовому представлению молекулы.
        mol = Chem.MolFromSmiles(smiles)
        if mol is None:
            logging.warning(f"Невалидный SMILES: {smiles}")
            return None

        # WHY: Удаление солей и фрагментов. ML-модель должна учиться на активном фармацевтическом ингредиенте (API), 
        # а не на хлориде натрия, который исказит расчетный молекулярный вес.
        uncharger = MolStandardize.rdMolStandardize.Uncharger()
        clean_mol = MolStandardize.rdMolStandardize.FragmentRemover().process(mol)
        clean_mol = uncharger.process(clean_mol)

        # WHY: Канонизация таутомеров. Разные таутомеры одной молекулы должны иметь одинаковый SMILES 
        # и дескрипторы, чтобы модель не считала их разными классами (проблема дублирования данных).
        # (Упрощенная реализация через канонический SMILES для стабильности)
        canonical_smiles = Chem.MolToSmiles(clean_mol, isomericSmiles=True)

        # Вычисление дескрипторов (измеримый результат)
        descriptors = {
            "MolWt": Descriptors.MolWt(clean_mol),          # WHY: Оценка способности проникать через мембраны (правило Липинского)
            "MolLogP": Descriptors.MolLogP(clean_mol),      # WHY: Гидрофобность, критична для растворимости и связывания
            "TPSA": Descriptors.TPSA(clean_mol)             # WHY: Полярная поверхность, предиктор проницаемости через ГЭБ (BBB)
        }
        return descriptors

    except Exception as e:
        logging.error(f"Ошибка обработки {smiles}: {str(e)}")
        return None

# Тестовый запуск
result = standardize_and_featurize("CC(=O)Oc1ccccc1C(=O)O.[Na+]") # Аспирин + ион натрия
print(result)
```

### ⚠️ ЧТО ВЫ НЕ УЧЛИ (СЛЕПЫЕ ЗОНЫ ПРОГРАММЫ):

1. **Data Versioning (DVC)**: В AI-factory критически важно версионировать не только код, но и химические датасеты. Изменение версии RDKit может изменить значения дескрипторов. Студент должен знать про `dvc` или `MLflow`.
2. **Activity Cliffs (Клифы активности)**: Студенты часто думают, что похожие дескрипторы = похожая активность. Нужно явно включить кейс, где малое изменение структуры (и дескрипторов) дает резкий скачок активности, и объяснить, почему линейные модели здесь ломаются.
3. **FAIR-принципы и регуляторика**: В Big Pharma пайплайн должен быть аудируемым. Логирование (которое я добавил в код) — это минимум. Нужно упоминать стандарты отчетности (например, для FDA/EMA).
4. **Масштабирование**: RDKit в цикле `for` работает медленно для 10M+ соединений. Нужно дать ссылку на `DataParallel` или `RDKit + Pandas apply` / `Dask` как следующий шаг после освоения базы.
