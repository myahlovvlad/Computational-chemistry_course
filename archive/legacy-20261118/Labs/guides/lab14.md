# Лабораторная работа 14. Передаваемый лабораторный конвейер

**Привязка:** [глава 14](../../Module_theory/Module%2014_SDLS-workflow%20development_web%20app.md). **Режим:** локальный CPU; сначала выполненный пример, затем новая задача. **Автор и аффилиация:** владелец курса заполняет при публикации. **Ориентир времени:** 60–120 минут для большинства работ; для QSPR и докинга дополнительно учитывайте запуск и разбор.

## Сущность и назначение

Проверить работу с чужим CSV, сохранность строк и один вычислительный контракт для CLI и интерфейса. Работа проверяет не только исполнение кода, но и допустимость вывода. До запуска сформулируйте ожидаемый результат и один случай, в котором алгоритму нельзя доверять.

## Данные и постановка кейса

molecules.csv; дополнительный ошибочный CSV без нужного столбца. Полное происхождение, единицы, тип данных и ограничения находятся в [паспорте datasets](../datasets/README.md). Искусственные значения не смешиваются с реальными измерениями. Каждый вход сохраняется с идентификатором и hash; генерируемые результаты записываются в `Labs/results/lab14/`.

## Workflow

**CSV contract → ядро → журнал всех строк → паспорт → CLI → проверка передачи.**

Разделите три этапа: проверка входа, применение метода и оценка результата. Успешный запуск не отменяет проверки химической формы, единиц, состояния модели и независимости сравнения.

## Guideline: пошаговый разбор

1. Вызовите табличную функцию напрямую и проверьте все статусы.
2. Запустите тот же конвейер как отдельный CLI-процесс.
3. Сравните ID и hash отчётов, затем откройте локальный Streamlit при желании.

Откройте [notebook](../notebooks/lab14.ipynb) и выполните ячейки сверху вниз с чистым ядром. Первая ячейка находит корень репозитория, затем задаются DATA/OUT. Следующая содержит полный код данного кейса с проверками. Последняя сохраняет `benchmark.json`: параметры, артефакты и время расчётной части. Ошибка assert означает, что результат нужно исследовать; удалять проверку ради прохождения нельзя.

Вставки `# WHY` и объяснения в теории связывают вызовы с научным смыслом. Если основной алгоритм вынесен в общий модуль, прочитайте его исходник по ссылке из notebook: общий код нужен, чтобы CLI, ноутбук и приложение использовали одну политику.

## Benchmark и критерии приёмки

CLI и прямой вызов сохраняют 12 строк и hash; отсутствующий столбец/повторный ID отклоняются; Streamlit — тот же pipeline.

Время измеряется на конкретном компьютере и не служит обещанием ускорения. Эталонные показатели проверенного запуска находятся в [сводном benchmark](../benchmarks/REPORT.md). Числа с плавающей точкой сравниваются с допуском, стохастические результаты — по явно указанным инвариантам. Наличие правильного ответа в книге не заменяет фактический запуск вашего кода.

## Тренировка и закрепление

2. Перенесите проект в новую папку и повторите запуск по README.
3. Как добавить другую политику, сохранив проверяемость результатов?

**Сдача:** notebook после Restart & Run All, таблица/рисунок из OUT, три предложения «наблюдение — ограничение — следующее действие». Не сдавайте только скриншот зелёной ячейки. Через 7 дней выполните первое упражнение на новом вводе без копирования ответа.

## Оценка

10 баллов: 2 за вход и происхождение, 3 за корректный запуск и проверки, 3 за интерпретацию, 2 за самостоятельный перенос. Обязательны сохранение ошибочных записей там, где это предусмотрено, отсутствие выдачи прогнозов за измерения и явный режим фактического исполнения тяжёлого инструмента.
