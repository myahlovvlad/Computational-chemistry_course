# Сопровождение компактного репозитория

В корне остаются `README.md`, `INSTRUCTIONS.md` и `THIRD_PARTY_NOTICES.md`. Программа и учебные материалы сохраняют свои пути; служебные документы размещаются в `docs`. Старые имена и новые места перечислены в [карте](../layout.json).

Изменения выполняются только в `main` единственного Windows-репозитория. WSL открывает те же файлы через ссылку; в `/home/miakhlov` не нужны отдельные клоны и копии курса. Системные `.config`, `.local`, `.vscode-server` и настройки оболочки не являются дубликатами курса.

Перед удалением нужно установить владельца файла, отсутствие ссылок и работающих процессов, затем различить воспроизводимый артефакт и уникальное свидетельство. Разрешённые кандидаты очистки — устаревшая виртуальная среда, кэш байткода, проверенная прежняя экспортная сборка и пустые временные каталоги. Книги, личное досье, первичные данные, outputs научных расчётов, checkpoint и тензоры интегралов не удаляются как «мусор».

Исторический `archive` содержит данные удалённых веток и не участвует в программе курса. Его файлы проверяются по исходным SHA и Git blobs. Не редактировать историю ради нового расположения документов; при изменении канонического файла сохранить прежние байты через `scripts/preserve_branch_dataset_versions.py` и проверить `scripts/verify_branch_datasets.py`.

Для обновления текущих отчётов:

```text
python scripts/update_course_status.py --observed-on YYYY-MM-DD
python scripts/check_repository_layout.py
python scripts/validate_course.py --out tmp/new-structure.json
```

Проверки сборки и фактического исполнения описаны в `scripts/README.md` и `.github/workflows/course-checks.yml`. Не повторять тяжёлый научный расчёт ради переноса документации. Не менять исходники четырёх файлов, закреплённых в плане активного TDDFT-запуска, до его окончания.
