# Экспорт этого курса в Stepik через API

Источник курса — единственная ветка `main` этого репозитория. Stepik будет его платформенным представлением. Для начала переносим один урок в тестовый курс, проверяем его глазами ученика, затем переносим весь курс.

Подготовлены два инструмента: `parser/stepik_plan.py` составляет запросы без сети; `parser/stepik_send.py` отправляет их только с `--apply`. Сейчас поддержаны текстовые шаги и ссылки на полный пакет Notebook. Работа автоматических grader, сдача открытых ответов и публичный запуск курса требуют отдельной проверки.

## 1. Сначала поймём, что переносится

| Репозиторий | Stepik | Ресурс API |
|---|---|---|
| Весь курс | Курс | `courses` |
| M01…M14 | Модуль | `sections` |
| M01-L01…M14-L02 | Урок | `lessons` |
| Место урока в модуле | Связь | `units` |
| Отдельный MD-шаг | Редактируемый текстовый шаг | `step-sources` |

Связь `unit` обязательна: созданный урок сам по себе ещё не включён в модуль. API использует отдельные плоские endpoints. В JSON запроса ключ обычно единственный: `course`, `section`, `lesson`, `unit`; у шагов — **`stepSource`**, а список ответа называется **`step-sources`**. Эти имена взяты из [официального примера создания контента](https://github.com/StepicOrg/Stepik-API/blob/master/examples/create_content.py).

В текущей программе 14 модулей, 28 уроков и 212 исходных текстовых шагов. Экспортёр добавляет к каждому уроку шаг скачивания практики: получится 240 текстовых шагов и 311 запросов создания для полного переноса. Численные проверки не превращаются автоматически в задания Stepik.

## 2. Подготовим и проверим пакет

В PowerShell из корня репозитория:

```powershell
$coursePython = (Resolve-Path '.\scripts\environment\.venv-chem\Scripts\python.exe').Path
& $coursePython scripts/validate_course.py --out tmp/my-stepik-structure-v1.json
if (!(Test-Path -LiteralPath 'parser/dist/stepik-api-20261120-v2')) {
    & $coursePython parser/build.py --out parser/dist/stepik-api-20261120-v2
}
& $coursePython parser/validate_package.py parser/dist/stepik-api-20261120-v2
if (!(Test-Path -LiteralPath 'parser/dist/stepik-api-20261120-v2.zip')) {
    & $coursePython -m zipfile -c parser/dist/stepik-api-20261120-v2.zip parser/dist/stepik-api-20261120-v2
}
```

Каталог вывода должен быть новым. Если эта сборка уже существует, выберите другое имя и используйте его во всех следующих командах. В WSL команды те же с Python своей Linux-среды; вторую копию курса создавать не нужно.

Версия `stepik-api-20261120-v2` уже подготовлена в этой рабочей папке: её можно повторно проверить без пересборки. ZIP занимает около 10,3 MiB. Для свежей редакции выбирайте новое имя сборки, а не заменяйте файлы внутри проверенного пакета.

ZIP содержит весь необходимый переносимый пакет: Notebook, shared/data, исходники шагов и закреплённую среду. Ученик скачивает и распаковывает его целиком. Один `.ipynb` без связанных данных не является самостоятельной поставкой.

## 3. Разместим файлы и получим настоящие URL

API-текст не может использовать путь вида `../../data/file.csv` из вашего компьютера. Ссылки между перенесёнными шагами инструмент заменит ссылками Stepik. Остальным материалам нужны доступные ученику HTTPS-адреса.

Разместите ZIP на подходящем файловом хостинге или как release asset GitHub. Для отдельных уже опубликованных файлов репозитория можно использовать базовый URL конкретного commit. Загрузка и проверка доступности файлов выполняются отдельно от этого текстового импортёра.

Встроенные дополнительные файлы Stepik, по текущей [справке платформы](https://help.stepik.org/article/54826), доступны в платных курсах и ограничены 25 MB на файл. Поэтому сначала проверьте размер ZIP и возможности своего курса. Файл нужно не только прикрепить, но и дать ученику ссылку на него.

## 4. Составим план одного урока без сети

Для проверки возьмём M11-L02: в нём есть формулы, код, таблицы, данные и практическая работа.

```powershell
& $coursePython parser/stepik_plan.py parser/dist/stepik-api-20261120-v2 --only M11-L02 --out tmp/my-stepik-M11-draft
```

Статус `BLOCKED_ASSETS` и код выхода 2 здесь ожидаемы: инструмент сохранил `requests.json` и список отсутствующих адресов `assets-template.json`. Он ничего не отправлял. Заполните копию шаблона, например `tmp/my-stepik-assets.json`. Ключ `$bundle` — ссылка на весь ZIP; остальные ключи — конкретные пути материалов. Пустые строки нужно заменить реальными URL.

Для файлов, опубликованных в GitHub, можно задать общий неизменяемый адрес:

```powershell
$revision = git rev-parse HEAD
$fileBase = "https://raw.githubusercontent.com/myahlovvlad/Computational-chemistry_course/$revision/"
& $coursePython parser/stepik_plan.py parser/dist/stepik-api-20261120-v2 --only M11-L02 --assets tmp/my-stepik-assets.json --file-base $fileBase --out tmp/my-stepik-M11-ready
& $coursePython parser/stepik_send.py tmp/my-stepik-M11-ready/requests.json --state tmp/my-stepik-M11-state.json
```

Последняя команда без `--apply` также не делает сетевых запросов. `READY_FOR_REVIEW` означает, что адреса назначены; их действительная доступность ещё не проверена. Откройте ZIP-ссылку как будущий ученик и убедитесь, что версия архива соответствует выбранной сборке. Для файлов, которых нет по общему GitHub-адресу, задайте отдельные URL в assets JSON.

## 5. Получим доступ к API

Создайте приложение в [Stepik OAuth Applications](https://stepik.org/oauth2/applications/): `Client type = Confidential`, `Authorization grant type = Client credentials`. Это поток из [официального OAuth-примера](https://github.com/StepicOrg/Stepik-API/blob/master/examples/oauth_auth_example.py).

```powershell
$env:STEPIK_CLIENT_ID = Read-Host 'Client ID'
```

Секрет вводится скрыто при запуске отправщика, хранится только в памяти и не записывается в план или state. Присылать его в чат или коммитить в Git не нужно. Токен получается через `POST /oauth2/token/`, дальнейшие запросы содержат `Authorization: Bearer …`.

До реальной отправки нужно исправить любую ошибку TLS. Пробный неавторизованный GET из текущей локальной Python-среды был остановлен проверкой сертификата (`CERTIFICATE_VERIFY_FAILED: certificate has expired`). Из этого нельзя установить, виноваты ли сервер, цепочка доверия или локальная среда. Проверяйте время, сертификат и доверенную цепочку; не отключайте проверку TLS. Живой импорт на этой машине пока NOT_RUN.

## 6. Создадим только пустой тестовый курс

```powershell
& $coursePython parser/stepik_send.py tmp/my-stepik-M11-ready/requests.json --state tmp/my-stepik-M11-state.json --course-only --apply
```

Это уже действие в Stepik: создаётся курс с названием `[ПРОВЕРКА] …`, его ID сохраняется в state. Откройте курс в преподавательском интерфейсе и проверьте, что он остаётся черновиком с подходящими правами доступа. Название само по себе не задаёт приватность. Публичная публикация инструментом не выполняется.

Именно здесь создаётся первый объект:

```json
{"course":{"title":"[ПРОВЕРКА] Основы хемоинформатики и вычислительной химии"}}
```

Сервер возвращает `courses`; ID берётся из `courses[0].id`, а не из отдельного вложенного endpoint.

## 7. Перенесём содержимое пилотного урока

После проверки черновика:

```powershell
& $coursePython parser/stepik_send.py tmp/my-stepik-M11-ready/requests.json --state tmp/my-stepik-M11-state.json --course-ready --apply
```

Флаг `--course-ready` фиксирует вашу проверку доступа. Инструмент создаёт section, lesson, unit, затем step-sources. Уроки запрашиваются с `is_public=false`; если сервер не подтверждает это поле, отправка останавливается для проверки доступа. Возможности зависят от аккаунта и актуальной схемы платформы; не обходите отказ автоматическим открытием урока.

Созданные ID сохраняются после каждого ответа. Повтор того же неизменённого плана с тем же state пропускает уже подтверждённые POST. Если связь оборвалась после отправки и неизвестно, создан ли объект, остаётся `pending`; инструмент не повторит такой POST вслепую. Сначала найдите объект в Stepik и согласуйте его ID с журналом. Не удаляйте state ради «чистого повтора»: это создаст риск дубликатов.

## 8. Проверим перенос по API и глазами ученика

```powershell
& $coursePython parser/stepik_send.py tmp/my-stepik-M11-ready/requests.json --state tmp/my-stepik-M11-state.json --verify --report tmp/my-stepik-M11-verification-v1.json
```

Проверка делает GET созданных объектов и сравнивает связи, позиции, названия, видимость уроков и HTML шагов с планом. Изменение HTML сервером даёт `REVIEW_REQUIRED`. При неполном импорте PASS не выставляется. Порядок GET course → sections → units → lessons → step-sources также показан в [официальном примере обратного экспорта](https://github.com/StepicOrg/Stepik-API/blob/master/examples/export_course.py).

Затем вручную проверьте:

1. Формулы RMSD, top-1 и долей: индексы, корни, знак строгого неравенства и Å.
2. Код: сохранены отступы и переносы; текст не перепутан с исполняемым заданием.
3. Переходы между шагами, таблицу интерпретации и последовательность раскрытия результатов.
4. Скачивание ZIP, распаковку и фактический запуск Notebook с shared/data.
5. Доступность файлов с правами ученика, а не только автора.
6. Сдачу ответа и обратную связь: этот импорт ещё не создаёт рабочий grader или приём открытых файлов.

GET-сравнение не проверяет визуальное отображение формул, правдоподобие научного вывода и обучение студента. Stepik поддерживает математические формулы в [текстовых шагах](https://help.stepik.org/article/54792); фактическое отображение импортированного LaTeX требует этой проверки.

План помечает особенно длинные тексты для просмотра. Если шаг неудобно читать, разделяйте его на осмысленные MD-шаги в репозитории и пересобирайте пакет. Самостоятельные правки только в Stepik разойдутся с единым источником курса. Автоматически рубить формулу или код по длине строки не нужно.

## 9. Перенесём весь курс после пилота

Создайте новый план без `--only`, новый state и новый пустой тестовый курс. План пилота остаётся отдельным свидетельством:

```powershell
& $coursePython parser/stepik_plan.py parser/dist/stepik-api-20261120-v2 --assets tmp/my-stepik-assets-full.json --file-base $fileBase --out tmp/my-stepik-full-ready
```

Если появились новые отсутствующие адреса, заполните их и соберите план в новом каталоге. Далее повторите создание пустого курса, проверку черновика, отправку и GET-проверку. Текущий инструмент создаёт новые объекты; обновление изменённого пакета через PUT по ранее сохранённым ID — отдельная операция, которую он не автоматизирует.

Перед публичным запуском нужно решить оставшиеся научные и педагогические вопросы, адаптировать 25 численных контрактов к выбранным типам заданий Stepik и проверить открытые ответы. Успех передачи текстов не закрывает эти этапы. Публикацию выполняйте отдельным осознанным шагом в настройках курса после проверки [условий публикации](https://support.stepik.org/hc/en-us/articles/360000172414-How-to-create-a-course-or-a-lesson).

## Те же Python-инструменты в WSL

PowerShell-переменные из примеров выше не являются синтаксисом Bash. В общей папке Windows/WSL сначала выберите Linux-среду, которую напечатал установщик:

```bash
cd ~/Computational-chemistry_course
# При необходимости: bash scripts/setup-linux.sh chem
course_python="$PWD/scripts/environment/.venv-linux-chem/bin/python"
export STEPIK_CLIENT_ID="ваш Client ID"
"$course_python" parser/validate_package.py parser/dist/stepik-api-20261120-v2
"$course_python" parser/stepik_plan.py parser/dist/stepik-api-20261120-v2 --only M11-L02 --out tmp/my-wsl-stepik-plan
```

Если установщик использует `.venv-chem/bin/python`, укажите этот фактический путь. Все параметры Python-инструментов одинаковы для Windows и Linux.
