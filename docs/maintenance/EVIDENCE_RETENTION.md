# Что можно очистить в practicuum/evidence

Снимок 20.11.2026: **167 каталогов, 713 813 869 байт ≈ 680,7 MiB**. Это объём до добавления небольших журналов текущей редактуры; работающий расчёт также может дописывать файлы. Каталог не является обычным кэшем.

| Содержимое | Назначение | Что делать |
|---|---|---|
| Первичные PDF/XML, таблицы и provenance | Проверка опубликованных чисел и условий | Сохранять; учитывать права на распространение |
| result/failure, протокол, версии, SHA и журналы | Воспроизведение положительных и отрицательных результатов | Сохранять вместе; FAIL не является мусором |
| Геометрии, SDF, Hessian, позы и прогнозы | Исходные научные outputs для повторного анализа | Сохранять; Notebook и сборка используют часть этих файлов |
| checkpoint, restart и входы активного расчёта | Возможность продолжения дорогого запуска | Не удалять до завершения и отдельного решения о хранении |
| Копии входов в старых автопрогонах | Фиксация версии данных конкретного запуска | Возможна дедупликация по SHA с изменением всех потребителей и проверкой архивных контрактов |
| executed.ipynb и повторные графики | Техническое свидетельство выполнения | Можно вынести в проверенный внешний архив, сохранив журнал, хеши, версии и доступность outputs |
| __pycache__, pyc, pyo | Воспроизводимый кэш Python | Можно удалить; в этом снимке **0 байт** |

Суммарный объём `executed.ipynb` — около **4,1 MiB**, меньше 1% всей папки. Удаление только этих файлов почти не уменьшит размер и усложнит аудит.

Самая крупная папка — `20261119-main-unification`, около 68,2 MiB. Там в том числе повторяются копии первичных PDF, закреплённые за разными прогонами. Папки конформерных исследований занимают примерно 35–47 MiB каждая; повторные Windows/Linux проверки также содержат копии Hessian. Это реальные данные и свидетельства проверок, а не временные файлы по одному лишь названию.

Следующий разумный шаг уменьшения — единое хранилище неизменяемых входов по SHA-256 и ссылки из receipts, затем проверяемый перенос старых технических прогонов в архив. Простое удаление `inputs`, старых дат или всех FAIL нарушит воспроизводимость. Для этой операции нужен отдельный перенос потребителей, а не команда удаления по маске.

Текущий аудит **ничего не удаляет**. Он обнаруживает буквальные ссылки из действующих исходников и защищённые пути архивного реестра; динамические пути Python и ручное использование могут не попасть в список. Метка REVIEW означает необходимость разбора, а не разрешение удалить каталог.

Полный список — [машинный инвентарь](EVIDENCE_INVENTORY.json). Исходники аудита — `scripts/audit_evidence.py`. Внешний резервный архив WSL и большой DF-кэш находятся отдельно; их удаление не является очисткой этой папки и может уничтожить возможность продолжения расчёта.
