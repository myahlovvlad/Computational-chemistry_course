# Лабораторная работа 4. Осмысленные дескрипторы

**Привязка:** [глава 4](../../Module_theory/Module%204_Descriptor.md). **Режим:** локальный CPU; сначала выполненный пример, затем новая задача. **Автор и аффилиация:** владелец курса заполняет при публикации. **Ориентир времени:** 60–120 минут для большинства работ; для QSPR и докинга дополнительно учитывайте запуск и разбор.

## Сущность и назначение

Посчитать признаки и отличить нулевое значение, пропуск и контекстное предупреждение. Работа проверяет не только исполнение кода, но и допустимость вывода. До запуска сформулируйте ожидаемый результат и один случай, в котором алгоритму нельзя доверять.

## Данные и постановка кейса

Те же 12 строк; признаки рассчитываются только для валидного parent. Полное происхождение, единицы, тип данных и ограничения находятся в [паспорте datasets](../datasets/README.md). Искусственные значения не смешиваются с реальными измерениями. Каждый вход сохраняется с идентификатором и hash; генерируемые результаты записываются в `Labs/results/lab04/`.

## Workflow

**Стандартизация → признаки с единицами → четыре условия Ro5 → объяснение.**

Разделите три этапа: проверка входа, применение метода и оценка результата. Успешный запуск не отменяет проверки химической формы, единиц, состояния модели и независимости сравнения.

## Guideline: пошаговый разбор

1. Сравните этанол и бензол качественно до расчёта.
2. Выведите MW, MolLogP, TPSA, HBD, HBA и число предупреждений.
3. Проверьте полиол, для которого важны HBD/HBA, а не только масса и липофильность.

Откройте [notebook](../notebooks/lab04.ipynb) и выполните ячейки сверху вниз с чистым ядром. Первая ячейка находит корень репозитория, затем задаются DATA/OUT. Следующая содержит полный код данного кейса с проверками. Последняя сохраняет `benchmark.json`: параметры, артефакты и время расчётной части. Ошибка assert означает, что результат нужно исследовать; удалять проверку ради прохождения нельзя.

Вставки `# WHY` и объяснения в теории связывают вызовы с научным смыслом. Если основной алгоритм вынесен в общий модуль, прочитайте его исходник по ссылке из notebook: общий код нужен, чтобы CLI, ноутбук и приложение использовали одну политику.

## Benchmark и критерии приёмки

MW этанола 46,069±0,01; TPSA бензола 0; контрольный полиол нарушает HBD/HBA.

Время измеряется на конкретном компьютере и не служит обещанием ускорения. Эталонные показатели проверенного запуска находятся в [сводном benchmark](../benchmarks/REPORT.md). Числа с плавающей точкой сравниваются с допуском, стохастические результаты — по явно указанным инвариантам. Наличие правильного ответа в книге не заменяет фактический запуск вашего кода.

## Тренировка и закрепление

1. Восстановите формулу счётчика четырёх нарушений.
2. Найдите два признака, которые могут быть связаны, и объясните, почему это не две независимые причины активности.
3. Объясните отличие logP от logD(pH).

**Сдача:** notebook после Restart & Run All, таблица/рисунок из OUT, три предложения «наблюдение — ограничение — следующее действие». Не сдавайте только скриншот зелёной ячейки. Через 7 дней выполните первое упражнение на новом вводе без копирования ответа.
