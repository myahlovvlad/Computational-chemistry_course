# ARCHITECTURE — каноническая образовательная система

Служебные документы размещены в `docs/status`, `docs/history`, `docs/architecture`, `docs/maintenance`. Карта переноса — [layout.json](../layout.json), навигация — [индекс документации](../README.md). В корне остаются только README, инструкции агента и правовые уведомления. Генератор статусов использует карту переноса; CI проверяет, что старые отчёты не появляются снова.

**Действующий источник:** ветка `main`, корень репозитория. Основание — выбранная автором редакция `course/unified-research-structure` с сохранением незакоммиченных данных на 19.11.2026. Другие ветки не служат параллельными версиями курса.

## Единственная модель содержания
- Программа: `programm/COURSE_BLUEPRINT.md`, 14 модулей/28 уроков.
- Каждый урок: вопрос → явные входы/источники/формы/единицы → модель → воспроизводимое исполнение → интерпретация и ограничения → перенос B → досье и план экспериментальной проверки.
- Траектория A: guided (истрадефиллин, ксантины); траектория B: independent (аторвастатин, HMGCR). Контрольные H2, ESOL, 1IEP не переименовывать в фактические данные A/B.
- На каждый урок: теория/малые MD-этапы и **два** Notebook, guided + independent. Обязательная самостоятельная защита научного вывода не заменяется автотестом.
- Единое `my_research` досье и междисциплинарная карта с provenance, условиями, методами, версиями, неопределённостью и историей решений.

`practicuum/evidence/` — неизменяемые отчёты/команды/хеши по конкретной версии.
`scripts/` — Windows/Linux/WSL и независимые uv профили.
`media/` — оригинальные и лицензионно допустимые визуальные/видео-ресурсы.

`archive/` — исторический материал, не подключённый к сборке.

## Правила единственного источника истины
1. Исходный авторский MD редактируется один раз; учебный Notebook/пакет генерируется, а не ведётся как независимая копия.
2. Старые `Module_theory/`, `Labs/`, `Stepik_course/`, `course_source/` — только архив/материалы миграции после проверки.
3. Не использовать вторую систему зависимостей в корне; выбрать канонические `scripts/environment`, старый lock только как сравниваемое доказательство.
4. Единый реестр `docs/status/course-status.json`; этапы реализации, исполнения, научной и педагогической экспертизы, Stepik, публикации независимы.
5. Лабораторная B требует осмысленной самостоятельной работы; прохождение пустого каркаса не означает PASS решения.
6. Научная метка: measured / literature / calculated / simulation / hypothesis с источником, условиями и пределами. Это точные значения схемы `dossier_records.py`.
7. Существующий контроль Vina 1IEP ≠ redocking A2A/HMGCR; PySCF B3LYP/STO-3G ≠ экспериментальная валидация UV; аппроксимация HPLC ≠ доказанная специфичность.
8. Исторические файлы и научные входы сохранять с hash и лицензиями; при конфликте чисел — REVIEW.

## Профессиональные вычисления и доказательства

`scripts/run_research_quantum.py`, `prepare_target_docking.py`, `run_target_redocking.py`, `fetch_target_qsar.py`, `train_target_qsar.py` — отдельные ресурсные маршруты. Полные расчёты выполняются из IDE/CLI в новом каталоге `practicuum/evidence`; исходные результаты, неудачные попытки и условия допуска сохраняются. Notebook раскрывает метод и различает новый расчёт и повторный анализ готового результата. Linux-only зависимости находятся в отдельных quantum/docking профилях uv.

`scripts/analyze_hplc_research.py`, `analyze_statin_research.py`, `analyze_caffeine_kinetics.py` анализируют первичные числовые данные, сохраняя границы идентифицируемости. `audit_target_qsar.py` отдельно проверяет каркасы, row IDs, прогнозы и отсутствие query-утечки. Переносимые снимки данных и их SHA находятся в `practicuum/shared/data`; большие checkpoint остаются в вычислительной среде, с сохранённым маршрутом к ним.

Технический PASS не снимает научный FAIL или BLOCKED. В частности, девять завершённых Vina-поисков с top-1 recovery 0/9 не валидируют ранжирование; сошедшаяся DFT-геометрия без numerical convergence и Hessian не объявляется подтверждённым минимумом. Статусы научной рецензии и студенческого пилота независимы от этих вычислительных gates.

## Исследование конформеров и native quantum-core

`setup_xtb.py` устанавливает SHA-проверенный локальный xTB; `run_conformer_research.py` выполняет полный поиск, сохраняет все попытки, идентичность графа/стереохимии, SCC, оптимизацию и реальные Hessian. `audit_conformer_numerics.py` отдельно проверяет ALPB grid и Hessian step. Общая `conformer_ensemble.py` содержит симметрийный conformer RMSD и mass-weighted SVD projection; docking использует другой, receptor-frame RMSD. Канонический bundle содержит сырые Hessian, геометрии, native и независимо пересчитанные частоты; M06 повторяет расчёт из матриц, внешний xTB внутри обычного Notebook не запускается.

Профиль uv `quantum-core` допускает официальный Windows PySCF 2.15.1 для SCF/TDDFT; полный `quantum` с dispersion/optimizer остаётся Linux. `run_vertical_tddft.py` задаёт отдельный composite CAM//GFN2 протокол, не присваивая ему чужой статус DFT-оптимизации. После реального ENOSPC добавлен scratch preflight 50 GiB и отдельный scratch directory; method/basis не уменьшаются при недостатке ресурсов. Inputs, failure и очистка только собственного незавершённого интегрального кэша документированы.
