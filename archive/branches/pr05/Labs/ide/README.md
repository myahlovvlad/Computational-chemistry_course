# Приложения и командные инструменты: работа через IDE

В модуле 14 код CLI и GUI пишется в файлах проекта. Jupyter служит для разбора готового вычислительного контракта и для журнала результатов самостоятельных кейсов. Сервер Streamlit из notebook не запускается.

## 1. Открыть рабочее место

В Ubuntu перейдите в корень курса и выполните `code .`. Проверьте подключение VS Code к WSL, выберите `.venv/bin/python`, откройте встроенный терминал. Сверьте `uv run --frozen python -c "import sys; print(sys.executable)"` с паспортом notebook. Установка описана в [SETUP.md](../SETUP.md).

Создайте в IDE собственный каталог:

```text
student_work/module14/
  core.py           # адаптер к вычислительному контракту, без копирования химической политики
  cli.py            # аргументы, чтение файла, вызов ядра, сохранение результата
  app.py            # ввод/отображение/скачивание, без отдельной химической логики
  test_core.py      # содержательные проверки схемы и сохранности строк
  evidence/         # argv, stdout/stderr, JSON/CSV и заметки браузерных проверок
```

Готовые `Labs/pipeline.py` и `Labs/app.py` — материалы для изучения существующей реализации. Они не считаются вашей самостоятельной работой и не заменяют полный итоговый проект. Переключатель таутомеризации в готовом приложении не реализован: не выдавайте фиксированную политику за переключаемую.

## 2. Кейс CLI: от файла к полному отчёту

1. Запишите контракт входа: UTF-8 CSV, непустые уникальные `id`, колонка `smiles`, правила обработки ошибочного SMILES.
2. В `core.py` вызовите общий pipeline курса или выделите свой проверяемый адаптер. Проект запускается из корня; для импорта готового ядра явно добавьте `ROOT/Labs` в `sys.path`, либо оформите пакет. Не поддерживайте два разных алгоритма для CLI и GUI.
3. Реализуйте аргументы `--input` и `--out`, контролируемый ненулевой exit code при нарушении схемы, сохранение всех результатов и passport. Числа и ID не должны теряться при сериализации.
4. Запустите отладчик IDE на неправильной схеме и на валидном CSV с invalid SMILES. Ошибка схемы отклоняет файл; invalid SMILES остаётся строкой результата.
5. Выполните тесты и реальные процессы; сохраните stdout/stderr и коды возврата.

Команды после реализации:

```bash
uv run --frozen python -m unittest discover -s student_work/module14 -p 'test_*.py' -v
uv run --frozen python student_work/module14/cli.py --input Labs/datasets/molecules.csv --out student_work/module14/evidence/valid
```

Негативные fixtures создайте в собственном каталоге. Не редактируйте исходные datasets и химические эталоны, чтобы пройти тест.

## 3. Кейс GUI: поверх того же ядра

В IDE реализуйте загрузку, ограничения 1 MiB / 500 строк, видимую текущую политику, все ID/status/reason и скачивание полного отчёта. Исходный пользовательский текст отображайте безопасно; ошибка должна оставаться понятной и после повторной загрузки.

```bash
uv run --frozen streamlit run student_work/module14/app.py --server.address 127.0.0.1
```

Из браузера проверьте валидный файл, отсутствие колонки, дубликаты, пустые/невалидные структуры, превышение лимитов и скачанный файл. Сравните скачанный результат с CLI по ID, статусам, hash входа и политике. Скриншот не заменяет содержимое скачанного артефакта. Не ставьте декоративный переключатель химической политики: обе ветви требуют реализации и тестов ядра, а выбранное значение — записи в passport.

## 4. Сдача и защита

Во втором notebook модуля 14 укажите пути к исходникам IDE, точные команды и exit codes, ссылки на outputs и ограничения. Передайте пакет другому человеку для повторения. Отдельно сдайте научное досье: происхождение данных, параметры, отрицательные контроли, интерпретация и следующий эксперимент. Непроведённый docking/QM/transfer помечайте явно. Автоматическая проверка JSON не выставляет оценку за интерфейс, независимый перенос или защиту.
