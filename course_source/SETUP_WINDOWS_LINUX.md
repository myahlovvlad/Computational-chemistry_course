# Установка рабочего окружения — Windows и Linux

**Редакция:** 2026-11-17. **Назначение:** пилот двух Jupyter Notebook модуля 1 и будущие практикумы.
**Условия:** обычный персональный ПК с Python 3.11/3.12 и доступом к пакетам. Для тяжёлых задач (RDKit, Vina, PySCF, MD) потребуются дополнительные модульные инструкции. Сочетания конкретных версий пока **не прошли матрицу проверок ОС**.

## 1. Что нужно

- Python 3.11 или 3.12 x64, установленный из официального источника. Убедитесь, что команда Python доступна в терминале.
- Git (удобно для клонирования, но можно скачать архив репозитория).
- Свободное место для локального окружения Python, права записи в рабочую папку.
- Среда JupyterLab; для модуля 1 используется matplotlib и стандартная библиотека Python.

Путь до рабочей папки лучше выбрать без ограничений на запись. Используйте один каталог репозитория, не запускайте работу из системных защищённых директорий.

## 2. Получение проекта

```sh
git clone https://github.com/myahlovvlad/Computational-chemistry_course.git
cd Computational-chemistry_course
```

Если Git недоступен, скачайте архив проекта через GitHub и распакуйте его. Все команды ниже выполняются из **корня репозитория**. Не требуйте подключения к сети после первоначальной установки базовых пакетов.

## 3. Windows 10/11 (PowerShell)

```powershell
py -3.12 --version
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r course_source/requirements-notebooks.txt
.\.venv\Scripts\python.exe -m jupyter lab
```

При отсутствии `py -3.12` используйте команду с действительно установленным `python`, сначала проверьте `python --version`. Прямой вызов исполняемого файла из `.venv` не требует активации и не зависит от PowerShell ExecutionPolicy. Не советуйте глобально понижать политику безопасности ради запуска блокнота.

## 4. Linux (bash)

```bash
python3 --version
python3 -m venv .venv
./.venv/bin/python -m pip install --upgrade pip
./.venv/bin/python -m pip install -r course_source/requirements-notebooks.txt
./.venv/bin/python -m jupyter lab
```

Если `python3 -m venv` отсутствует, установите поддержку виртуальных окружений средствами пакетного менеджера **вашего** дистрибутива. Для Astra Linux, Ubuntu, Fedora и других систем набор системных пакетов может различаться. Не устанавливайте Python-библиотеки курса в системный интерпретатор с ключом `--break-system-packages`.

## 5. Как открыть два блокнота

После запуска `jupyter lab` браузер откроет локальную рабочую область. Перейдите к:

- `course_source/modules/M01/01_guided_case.ipynb` — разобранное исследование.
- `course_source/modules/M01/02_independent_lab.ipynb` — самостоятельная лабораторная.

Выберите kernel, соответствующий вашему `.venv`. Выполните `Kernel → Restart Kernel and Run All Cells`. В первом блокноте должны появиться численные эффекты и график. Во втором TODO остаются незаполненными, но блокнот не должен падать; после решения задач его результат изменится.

## 6. Контроль среды (smoke test)

В новой ячейке Jupyter:

```python
import sys, matplotlib, IPython
print(sys.executable)
print(sys.version)
print(matplotlib.__version__)
```

Путь в `sys.executable` должен указывать на созданное `.venv`. Если путь другой, смените kernel. Не используйте одно удачное выполнение import как доказательство научной корректности моделей.

Для автора и CI: `python -m unittest discover -s course_source/modules/M01/tests -p "test_*.py" -v` из активированной среды или через явный путь к `.venv` Python.

## 7. Если не запускается

- `ModuleNotFoundError`: сравните `sys.executable` в Notebook с Python, которым установлены пакеты; установите в ту же среду и перезапустите kernel.
- `FileNotFoundError`: выполните Jupyter из корня репозитория, проверьте текущую директорию через `Path.cwd()`.
- Нет прав на папку: переместите репозиторий в домашнюю пользовательскую директорию.
- График не выводится: перезапустите kernel, проверьте matplotlib и выполните код после импорта.
- Не работает скачивание: используйте заранее подготовленный поддерживаемый набор пакетов, официальные репозитории или помощь системного администратора; не предлагайте отключать TLS-проверки.

## 8. Когда нужна IDE

Jupyter используется для исследования, проверки гипотез, расчётов, визуализации, воспроизводимого учебного отчёта. Когда лабораторная требует создать приложение, CLI, библиотеку или интерфейс, переходите в IDE (например, VS Code/PyCharm) и создавайте обычные исходные файлы и тесты. Notebook может демонстрировать вызов реализованного кода, но не подменяет структуру программы.

Официальные источники: https://jupyter.org/install ; https://docs.python.org/3/library/venv.html ; https://jupyterlab.readthedocs.io .
